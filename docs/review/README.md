# review 目录

> 类型:目录说明。
> 性质:现行文档。
> 归属:文档自身。
> 适用版本:平台 `4.0.5`。

本目录存放**问题清单**——回答"现在还有哪些事要做"的唯一来源。

## 文件名怎么读:`4_0_5a.md`

- 前半段是**平台版本**:`4_0_5` = 平台 `4.0.5`。版本号本身只有三位数字,**不带任何后缀**。
- 末尾的单个字母是**文档轮次**:同一个 PATCH 可能要反复 review,每修订一次就换一个字母(`a` → `b` → `c` …)。所以 `4_0_5a` 读作"**平台 4.0.5 这一版清单的第 a 稿**"。
- 文件名里的 `a` 只用于区分文档,**不是版本号的一部分**;真要发布时版本仍然是 `4.0.5`。
- 同一版本内换稿时**新建文件**(`4_0_5b.md` …),旧稿移入本目录的 `归档/` 或直接删除——任何时刻只有最新一稿是现行清单,本 README 的"目录内容"表随之更新。

## 清单怎么用

- `4_0_5a.md` **只列要做的事**:做完一条就删掉该行,不在清单里留"已修复"记录,git 历史就是修复记录。
- 编号(条目 1–55、§5 的 A-01…A-11)是**稳定 ID**:沿用上一版《汇总报告》的编号,**空缺的号码表示该条已做完并已删除**。改动清单时**不要重编号**,否则别处文档里的"条目 N"会全部失效。
- 章节编号同样沿用旧稿,所以清单里**没有 §4**——那是归档版才有的"已修复 / 已失效"章节。别处若引用"汇总报告 §1 / §2.1 / §4.x",指的都是归档件。
- 每条待办都带 `file:line` 证据;逐条判定与证据链见[审查日志/核验报告](../审查日志/核验报告.md)。
- 上一版清单已归档:[审查日志/归档/2026-10-12-全项目-问题汇总.md](../审查日志/归档/2026-10-12-全项目-问题汇总.md)(编号 1–53 由本稿沿用)。
