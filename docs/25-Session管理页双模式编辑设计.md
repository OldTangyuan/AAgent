# 25 Session 管理页双模式编辑设计

## 1. 目标与边界

在现有 `/sessions.html` 的值编辑区域提供「可视化 / JSON」模式切换。六种 Session 值类型都能在可视化模式下编辑；列表支持增删、排序与逐项编辑，`message` 和 `event` 有结构化表单。JSON 模式保留当前直接编辑完整值的能力，方便粘贴与批量修改。两种模式保存的是同一个 `value`，不增加存储字段和 API。

本方案只改变管理页的交互；Session ID、创建后固定的 `value_type`、保存时整值覆盖和 `updated_at` 乐观锁保持不变。`content` 仍用文本框，不要求将普通文本序列化为 JSON。参考现有 [Session 节点与管理页设计](23-Workflow%20Session节点与管理页设计.md)。

## 2. 类型与控件

| `value_type` | 可视化模式 | JSON 模式 |
|--------------|------------|-----------|
| `content` | 多行文本框 | 不显示切换；继续编辑原始文本 |
| `message` | `role` 下拉（`system`、`user`、`assistant`、`tool`）和 `content` 多行文本框 | 完整对象 `{ "role": "user", "content": "..." }` |
| `event` | `event_type` 非空文本框、`payload` JSON 编辑框、扩展字段 JSON 编辑框（默认 `{}`） | 完整 event 对象 |
| `list-content` | 逐行文本框，添加、删除、上移、下移；空字符串是合法项 | 字符串数组 |
| `list-message` | 每项展开为 `role` 与 `content`，提供添加、删除、上移、下移 | message 对象数组 |
| `list-event` | 每项展开为 `event_type`、`payload`、扩展字段，提供添加、删除、上移、下移 | event 对象数组 |

列表展示序号和简短内容摘要；每项控件保留原始顺序，删除需明确点击，不因空白字段自动删除。新增 message 项默认 `{ "role": "user", "content": "" }`；新增 event 项默认 `{ "event_type": "", "payload": {} }`，填写类型后才可保存。新建 Session 切换类型时，延续当前清空草稿的行为，但要先提醒会丢弃已编辑的值；`list-*` 从 `[]` 开始，`message` 和 `event` 使用上述初始结构，而不是当前通用的 `{}`。

当前后端对 message 要求**恰好** `role`、`content` 两个键；对 event 要求非空字符串 `event_type` 和存在 `payload`，允许额外顶层字段，`payload` 可以是任意合法 JSON 值。因此 event 可视化表单不能把 `payload` 限死为对象，也不能在切换模式后丢掉扩展字段。扩展字段编辑框仅接受 JSON 对象，不能覆盖 `event_type`、`payload`；空对象表示无扩展字段。JSON 编辑器显示完整原值，包括未知扩展字段，不做自动规范化或字段过滤。

## 3. 草稿与模式切换

选中记录时，将服务端 `value` 复制成页面草稿，初始模式为可视化（可沿用本页最近一次选择）；未保存编辑只修改草稿，不发请求。UI 表单写入结构化草稿，进入 JSON 模式时序列化该草稿并格式化显示；从 JSON 返回可视化模式时解析文本，先按当前 `value_type` 验证形状，成功才替换草稿并切换。语法或结构错误时留在 JSON 模式，显示具体错误，原始输入不丢失。event 的 `payload` / 扩展字段有错误时也保留原始输入，禁止切换或保存，指出对应项与字段；不要用旧草稿悄悄覆盖未解析的输入。

保存前从当前模式提交**完整值**，执行前端结构校验后调用现有 `createSession` / `updateSession`；后端继续负责权威校验及 1 MiB 限制。保存成功使用响应值更新草稿和版本；保存失败保留编辑内容与模式。`409` 显示“记录已更新，请先刷新”，不自动刷新或重放覆盖；刷新、选择另一条记录、删除、新建、取消时若有未保存修改，先确认丢弃，取消动作则留在当前编辑状态。取消只恢复最近一次成功读取或保存的值；创建模式取消返回空详情。不要通过后台轮询覆盖草稿。

JSON 模式输入无效时，不允许切回可视化或保存，但仍允许在确认丢弃后离开记录；这样既保留修复机会，也不会把一个旧的可视化值误保存。编辑器切换本身不调用 API。

## 4. 页面与实现位置

- 在 `manager_webui/static/sessions.html` 的值区域加入「可视化 / JSON」分段切换、按类型显示的编辑容器与逐项错误提示；`content` 只显示文本编辑。保存、取消、状态提示仍位于现有表单底部。
- 在 `manager_webui/static/sessions.js` 将取值、填表、渲染与校验按 `value_type` 组织，复用现有 `fetchSession`、`createSession`、`updateSession` 和版本字段；动态节点用 DOM API 创建并用 `textContent` / `.value` 写入，不注入任意 HTML。
- 在 `manager_webui/static/css/sessions.css` 调整列表项布局及移动端滚动区域，长 JSON 与长内容不撑破详情栏；更新 HTML 中变动资源的 `?v=` 版本号。
- 不修改 `manager_webui/sessions.py`、Agent 存储或接口协议。前端规则与后端 `valid_value` 对齐，后端仍是最终裁决者。

## 5. 验收

1. 六种类型均能创建、读取、在可视化模式编辑并保存；三个列表可增删和调整顺序，保存后刷新内容与顺序一致，空数组与空字符串项不丢失。
2. message 只能选合法 role，event 可以编辑非对象 `payload`，其扩展字段在 JSON -> 可视化 -> JSON -> 保存之后仍完整保留；无效字段给出定位明确的错误。
3. 两模式来回切换不发保存请求、不丢草稿；无效 JSON / 无效类型结构无法切回或保存，修正后可继续；取消和导航离开时按是否有修改处理。
4. 发生并发更新时返回 409 且输入不丢失；服务端拒绝超大值时同样保留草稿，手动刷新后才载入新值。
5. 在桌面和手机宽度验证列表行操作、键盘操作、错误提示、长文本与长 JSON 的滚动；`content` 原有文本编辑、复制 ID、搜索和删除仍可用。
