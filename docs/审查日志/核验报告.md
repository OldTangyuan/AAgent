## 1. 为什么要做这次核验

这批日志跨了 2026-08 到 2026-10,而项目在那之后经历了一次大重构:

- 旧事件驱动链整体删除——`active` / `tool_excute` / `rpc_apply` / `rpc_review` / `tool_return` / `handle_map` / `agent/command.py` / `agent/prompt/` / `agent/settings.json` / `agent/2.py` / `agent/3.py` 全部不存在了;
- `agent/task_worker.py` 被重写为「读事件绑定 → 发 `workflow` 事件 → 执行 Workflow」,全文只剩 3 个函数;
- `webui_py` 的 `workflows.py` / `models.py` / `documents.py` / `subagents.py` / `settings.py` 全部迁出,`webui_py/` 现在只剩 `main.py` / `common.py` / `events.py` / `event_bindings.py`;
- 新增了 `manager_webui`(8084)、`tool_server`(8083)、`tool_provider`,本地工具从 `agent/tools/` 迁到 `tool_provider/tools/`;
- 旧核心文档 `docs/00` ~ `docs/16` 全部移入 `docs/废弃旧文档/`。

结果是旧日志里大量条目**指向的代码已经不存在**,"过期"由此而来。本文件逐条判定它们现在是什么状态。

## 2. 判定口径

| 状态 | 含义 |
|---|---|
| **STILL** | 问题在当前源码中仍然真实存在,给出可直接验证的 `file:line` |
| **FIXED** | 当前源码已修正该问题 |
| **GONE** | 问题指向的代码/文件/文档已不存在,问题自动失效 |
| **MOVED** | 对象仍在但形态/位置/行为已变;已判定新形态下问题是否仍成立 |

补充口径(本报告统一):

- 判定只看**当前源码**,不采信历史报告的自述,不用文档判断代码;
- 若旧文件仍在且仍含该缺陷,即使它已经是**无人 import 的孤儿代码**,也记 STILL,并在说明里注明线上路径的实际状态;
- 四路取证各有一位核验人独立完成,交叉重复的条目(A 组与 D 组都碰到 A-06/A-07)已合并去重。
