# AAgent 文档

> 类型:目录说明。
> 性质:现行文档。
> 归属:文档自身。
> 适用版本:平台 `4.0.0+`。

本文件是 `docs/` 的**唯一入口**：登记每篇文档的类型、生命周期、归属与适用版本。规则来源见 [版本与归属规范](版本与归属规范.md)。

**一句话判据**：只有 `性质:现行文档` 的文档描述当前行为；标 `历史快照` / `已作废` 的只用于追溯。文档与源码冲突时，**以源码为准**。

## 元信息头怎么读

每篇文档开头都有四行（协议类文档另加 `协议版本`）：

| 字段 | 取值 | 含义 |
|---|---|---|
| `类型` | 设计文档 / 目录说明 / 索引清单 / 汇总清单 / 审查报告 / 审计报告 / 核验记录 / 实现记录 / 修复记录 / 流程规范 / 调研笔记 / 一次性产出 | 文档体裁 |
| `性质` | `现行文档` / `历史快照` / `已作废` | **决定还能不能信** |
| `归属` | 代码责任域（`agent/`、`tool_server/`… 或 `跨服务`、`文档自身`） | 改动了该责任域的契约面代码时，需要同步这些文档 |
| `适用版本` | 平台版本区间（如 `平台 4.0.0+`）或 `—` | 这篇文档对应哪个平台版本 |

## 维护约定

1. 新建文档必须带四字段元信息头（`类型` / `性质` / `归属` / `适用版本`），协议类文档加 `协议版本`。
2. `性质` 只降不升：`现行文档` 可以改为 `历史快照` 或 `已作废`，反向不允许。
3. 归档时移入对应目录的 `归档/`，正文只做机械调整（加归档说明、修相对链接），**不回写结论**。
4. 文档与源码冲突时以源码为准，并把过期文档改为 `历史快照` 或修正。
5. `归属` 的用途是**变更时反查**：改了某个服务的契约面代码，就要检查 `归属` 含该服务的现行文档。
